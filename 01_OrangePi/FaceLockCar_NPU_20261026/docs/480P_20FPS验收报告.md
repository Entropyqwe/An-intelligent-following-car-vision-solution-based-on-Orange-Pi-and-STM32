# 彩色480p、20FPS最低规格与实机验收

测试日期：2026-10-26。**当前整机未通过20FPS最低要求。** 本报告记录已完成的软件部署和实测，不把摄像头声明帧率、重复图像计算或无人画面当作完整人像跟踪验收。

## 1. 最低输出规格

| 项目 | 要求 / 当前配置 |
| --- | --- |
| 图像 | 彩色，真实采集640×480，BGR三通道 |
| 摄像头格式 | MJPEG，申请30FPS，实际出帧另行测量 |
| 完整处理帧率 | 至少20FPS；包含逐帧人体检测、身份核验调度、目标关联与界面显示 |
| 身份核验 | YuNet + SFace；未锁定逐帧核验，锁定后每3个处理帧核验一次 |
| 人体检测 | VIPLite NPU / YOLOv5，每个处理帧执行，保持原模型输入640×640 |
| 界面 | 头框合并ID、人体框、帧率、偏转角、模式与通信状态 |
| STM32链路 | 原S1、115200 8N1、独立10Hz发送；原转向配置和超时逻辑保留 |
| 自动验收 | 不少于60秒，扣前2秒热身；处理与NPU人体检测均≥20FPS；有效跟踪≥90%，连续有效≥10秒 |

有效跟踪比例等验收阈值是本轮为防止无人/未锁定场景误通过而增加的工程检查，不改变STM32控制判定。图像彩色/亮度自动检查仅为启发式，仍需人工查看。相机收到帧的时间不等于传感器曝光时间。

## 2. 已完成部署

- 新增 `run_balanced.sh`：固定彩色640×480 MJPEG、2个OpenCV线程、NPU人体检测、原转向逻辑、自动/手动双模式。
- 检测到稳定串口路径时自动启用原串口；未找到时仅预览，验收会报告串口未通过。
- 保留默认自动曝光，不使用实测过暗、过曝或识别失败的强制30FPS参数。
- 新增完整JSON指标和 `tools/acceptance_report.py`，记录真实处理帧率、有效跟踪、P95耗时、采集尺寸、图像统计和串口错误。
- 本机与板上34项测试通过；原STM32文件、协议/转向/跟踪核心和Output发送类校验未变化。板端图库未覆盖。

## 4. 采集瓶颈与已排除方案

这只摄像头标识为Microdia `0c45:64ab`。测试显示：

- 480p MJPEG自动曝光有效图像随场景约8.3～16.7FPS；720p此前同样约8.3FPS。
- 480p固定帧率MJPEG约29.95FPS，但默认画面均值仅约5/255，图像过暗。手动最小曝光值10时约30FPS，却明显过曝。
- 提亮/对比度/伽马组合能得到可见的彩色30FPS，但噪点重、识别不合格，已撤回；不将软件提亮算作画质修复。
- 480p YUYV本轮实测约14.9FPS，不采用。
- 调整50/60Hz防闪烁、增益、背光补偿及摄像头USB重置未获得合格20FPS图像。USB重置后固定约29.93FPS且过暗，动态自动曝光约8.34FPS。
- 摄像头驱动声明的60FPS不是实际有效帧率。

下一步需要固定镜头、让完整人脸与上半身进入画面中部，并增加人物正面照明后重新测量。若在该条件下仍不能提供20FPS有效画面，应进一步确认摄像头固件/曝光控制或更换经实测可用的摄像头，不能通过插帧、重复旧检测或降低身份阈值掩盖问题。

## 5. 算法与通信对照

以已采集到的真实ID 1人像反复运行20秒：NPU人体检测、CPU身份识别、目标关联、显示光流、HUD合成，2线程约23.2076FPS，4线程约20.1465FPS。重复图像条件下有效率100%。**不含实时相机和GUI呈现，不是实机跟踪验收，不证明运动目标下仍有该速度。** 保留2线程。

STM32实测：3秒1500中位测试连续收到 `#A1,...,1,1500,0`。A1证明MCU接受了命令，不能证明SG90物理轴角度。退出发送无效回中包；原固件超时逻辑未改。

## 6. 以后启动与复测

香橙派终端，先退出其他视觉窗口：

```bash
cd ~/FaceLockCar_NPU_20261026
bash run_balanced.sh
```

退出按Q。A切换自动/手动，U解锁，点击头框或数字键选择已登记ID，N显式登记。不自动录入陌生人。

保持人员入镜，进行65秒完整测速：

```bash
bash run_balanced.sh --max-seconds 65 --metrics-json logs/acceptance480_metrics.json
.venv/bin/python tools/acceptance_report.py logs/acceptance480_metrics.json --out logs/acceptance480_report.json
```

报告 `passed: true` 才代表上述自动检查通过；退出码2表示未通过。物理舵机动作仍须观察。原480p视场/转向参数沿用原配置；720p预览另用 `run_hd_preview.sh`，不要混用720p未核验的视场角控制。
